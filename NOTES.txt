CampusCart: Interview & Project Drive Master Guide
This guide is your ultimate study companion for your project drive and viva. It explains the technologies used, details the file and folder layout, explains how the key features work under the hood, and lists common interview questions with their answers.

🌟 1. Project Overview (The "Elevator Pitch")
CampusCart is a private peer-to-peer digital marketplace and utility portal designed exclusively for university campuses.

The Goal: To make student life more affordable, secure, and sustainable by allowing students to buy/sell secondhand goods (textbooks, gadgets, calculators) and report lost items directly to a localized campus board.
Why it's unique: Unlike public sites (like Craigslist or OLX), it restricts access to campus users, integrates an administrator dashboard for listing moderation/safety, uses base64 image compression to run without external database storage, and features high-fidelity glassmorphic micro-animations.
🛠️ 2. Core Technologies Used
In your interview, they will ask you to explain your tech stack. Here is the breakdown:

A. Frontend: Angular 18+ (Standalone architecture)
What it is: A modern web framework developed by Google for building single-page client applications using HTML, CSS, and TypeScript.
Key concepts used in CampusCart:
TypeScript: A statically typed superset of JavaScript that makes code less prone to errors.
Standalone Components: Modern Angular design that does away with heavy NgModules. Each component (e.g., LoginComponent, SellComponent) is independent and imports its own dependencies.
Angular Signals (signal, computed): A highly efficient reactive state management system. It notifies the UI to update only the specific parts of the screen that changed, leading to fast performance.
Modern Control Flow (@if, @else, @for): Streamlined built-in blocks for showing/hiding elements and listing arrays dynamically in the HTML.
Router (router-outlet): Manages navigating between page views (e.g., changing from /login to /dashboard/lost-found) without reloading the entire page.
B. Backend: Node.js (Custom REST API Server)
What it is: A JavaScript runtime environment that lets us run JavaScript code on the server side (outside the web browser).
Key concepts used in CampusCart:
HTTP Server (http module): A native Node.js module used to create the API server, listen for network requests on port 3001, and respond with JSON data.
File System (fs module): Used to read from and write to the local database file (db.json) in real-time.
Dynamic Host Binding: The frontend resolves the server hostname dynamically (window.location.hostname). This allows multiple devices (like a phone and a laptop) connected to the same college Wi-Fi network to access and share the same server instance.
C. Database: JSON Database (db.json)
What it is: A flat-file database format. All application records (users, products, notifications, lost & found reports) are stored in standard JSON format in a single file named db.json.
Why we used it: It eliminates the need for installing heavy database engines (like MySQL, MongoDB, or PostgreSQL) on the user's computer, making the project lightweight, portable, and easy to run anywhere.

⚙️ 4. How Key Features Work (Technical Mechanisms)
A. How Image Uploading Works without Cloud Storage (Base64 Pipe)
Problem: Normal websites upload files to clouds (like AWS S3). We wanted CampusCart to run locally without cloud accounts.
Mechanism: When a student uploads a picture in sell.component.ts or notices.component.ts, a JavaScript helper (FileReader) reads the image file and converts it into a Base64 Data URL (a long text string representing the image data).
Storage: This string is sent to the Node backend inside a JSON payload and saved directly in db.json as a text field. The frontend loads it inside standard <img> tags ([src]="product.image").
B. The Dual-Field Authentication Flow
Behavior: Users must provide both their Username/Full Name and their Email Address to sign in.
Logic: The frontend validates that both inputs are filled, then calls the backend /api/auth/signin API.
Matching: The server looks for a match where email matches the input, and the username matches the profile id or full_name. If it is a new user, it automatically creates a new profile on-the-fly, allowing seamless testing.
C. The Visual Success Overlay Animation
Behavior: When listing or updating an item, a full-screen glassmorphic card appears with confetti and an auto-redirect progress bar.
CSS Tricks:
Glassmorphism: Achieved via backdrop-filter: blur(8px); and semi-transparent backgrounds (rgba(15, 23, 42, 0.4)).
SVG Path Drawing: The checkmark is a vector graphic (<path>). In CSS, we animate the stroke-dashoffset property from the length of the path down to 0. This makes it look like the checkmark is being "drawn" dynamically.
confetti Sparkles: Multiple elements styled with random keyframe delays that translate (float) upwards and rotate (spin) in the background.
Auto-Redirect: A progress bar loads from width 0% to 100% over 2.2 seconds, synced with an Angular setTimeout timer that routes the user back to the feed.
D. The HD "Downloaded-Style" Video Hero
Behavior: The dashboard displays a looping video with zero YouTube logos, title cards, or volume controls.
Implementation:
Embeds the YouTube iframe of video qJDDpm2TOvE with parameters autoplay=1&mute=1&loop=1&playlist=qJDDpm2TOvE&controls=0&modestbranding=1&rel=0&vq=hd1080.
CSS Masking/Crop Trick: We place the iframe inside a container with overflow: hidden and pointer-events: none. The iframe is scaled up to 1.35 times its size (transform: scale(1.35)). This crops out the outer boundaries of the video player, effectively chopping off the YouTube watermark logo, title card, and playback progress bars, rendering it like a native background MP4 file.
❓ 5. Common Interview Q&As (Viva Preparation)
Q1: Why did you choose Angular instead of React for this project?
Answer: "Angular is a complete 'batteries-included' framework. It provides routing, form validation, and state management out of the box, whereas React requires installing multiple third-party packages. Additionally, Angular 18's new Standalone Components and Angular Signals make reactive state management extremely fast and easy to maintain."

Q2: What is the purpose of the api-server.js file?
Answer: "It is our lightweight backend server written in Node.js. It listens on port 3001, handles incoming HTTP requests (like POST for logging in, GET for loading listings), reads/writes to our local db.json database file, and coordinates image string conversion and notification dispatches."

Q3: How do you handle real-time data sync if two students use different devices?
Answer: "The Node.js server binds to port 3001 on the host machine. The Angular frontend uses the dynamic helper window.location.hostname to resolve the backend API address. This means if a laptop and a phone are on the same Wi-Fi network, the phone connects to the laptop's IP address on port 3001, and both interact with the exact same db.json database file in real-time."

Q4: What happens if a user uploads a huge 20MB image? Will it crash the database?
Answer: "To prevent database bloat, the frontend has a built-in file validation pipe. If a student uploads a file larger than 3MB, the upload is rejected with a warning message, and they are instructed to choose a compressed image. This keeps our JSON database running fast."

Q5: How does the admin moderation system protect the campus?
Answer: "Admins have a dashboard (verification.component.ts) that lists all active products. If a listing violates rules, the admin clicks 'Block'. This sets is_blocked = true on the item in db.json and notifies the seller. The seller can edit the item, which changes its status to verification_pending = true. The admin gets an alert, reviews the modifications, and can click 'Approve & Unblock' to make it visible on the market again."




A Beginner's Guide to Full-Stack Development (via CampusCart)
Welcome to the world of full-stack web development! If you are new to this field, seeing hundreds of files, components, and servers can feel overwhelming.

This guide is written specifically for beginners. It explains what "full-stack" means using simple analogies, shows how CampusCart fits this model, and walks you through a step-by-step example of how data flows from a user's click to the database.

🏛️ 1. What is "Full-Stack Development"?
A "Full-Stack" application is divided into three layers: Frontend, Backend, and Database. Think of a restaurant to understand how they work:

The Frontend (The Dining Area & Menu):
This is what the customer sees and interacts with. In web development, it is the website loaded in your browser (HTML, CSS, buttons, images).
The Backend (The Kitchen & Chef):
This is hidden from the customer. The chef receives the order from the dining area, prepares the food, decides how to cook it, and packages it. In web development, this is the server running on a computer that receives requests and executes logic.
The Database (The Pantry/Fridge):
This is where ingredients (data) are stored. The chef goes to the pantry to grab vegetables or store leftover food. In web development, this is where user accounts, items, and settings are saved permanently.
💻 2. How CampusCart implements the "Full Stack"
CampusCart is constructed exactly like the restaurant model:

Mermaid diagram
Layer 1: The Frontend (Angular 18)
What it does: Displays the login boxes, lists the products, plays the hero video, and runs the success checkmark animations.

Folder Location: Everything inside src/app/ represents your frontend.
Layer 2: The Backend (Node.js)
What it does: Listens for requests from the frontend, verifies credentials, blocks items, and adds notifications.

What it does: Remembers the profiles, active products, notice reports, and notifications.
Core Technology: JSON flat-file. Instead of running a database server (like Oracle or MongoDB), we write data directly into a text file called db.json.
Folder Location: The db.json file at the root of your project.

🧭 4. Core Concepts for Beginners
A. Client-Server Communication (API Endpoints)
The frontend and backend talk to each other using HTTP Requests (just like entering a URL in your browser). The backend defines specific paths called endpoints:

GET /api/products: Frontend asks: "Give me the list of products to display."
POST /api/products: Frontend says: "Here is a new product a student listed. Please save it."
DELETE /api/products/123: Frontend says: "Please delete the product with ID 123."
B. Reactive State Management (Signals)
In Angular 18, we want the screen to update instantly when data changes (e.g., when a new notification arrives).

We use Signals (signal()). A signal is a container that holds a value.
When the value inside the signal changes, Angular automatically refreshes only the HTML elements that use it. You don't have to manually refresh the browser page.
C. Base64 File Encoding
Since we don't have a file storage cloud, when a user selects a photo, the browser converts the binary file (PNG/JPG) into a long string of text characters (Base64).
This text string starts with data:image/png;base64,... and is sent to the server as standard text, then saved directly in db.json.
